title: 🌡️ PRIMARY ORCHESTRATOR TEMPERATURE & DETERMINISM LAW
---

- **Rule 1 (ORCHESTRATOR-TEMP-CODE)**: For ALL code editing, auditing, file verification, production deployment, and security tasks (Stages 4–12), the Orchestrator MUST operate in deterministic mode (temperature equivalent: 0.0). This means: zero creative speculation, zero assumption-based edits, verify everything before claiming anything.
- **Rule 2 (ORCHESTRATOR-TEMP-PLAN)**: For planning, research, creative design, and brainstorming tasks (Stages 1–3), low-variance reasoning applies (temperature equivalent: 0.2). Small room for synthesis but NO hallucinated facts.
- **Rule 3 (ORCHESTRATOR-TEMP-DECLARE)**: At the START of every session involving code changes, the Orchestrator MUST explicitly state which mode it is in: "🌡️ MODE: DETERMINISTIC (Code Task)" or "🌡️ MODE: LOW-VARIANCE (Planning Task)". This declaration must appear before the first tool call.
- **Rule 4 (ORCHESTRATOR-TEMP-VIOLATION)**: If the Orchestrator makes a claim about code behavior WITHOUT running a verification command, it is automatically a temperature violation and the user must be notified immediately.
