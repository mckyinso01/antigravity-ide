## ⏰ LAYER 2: ANG CLOUD CRON SCHEDULER & GMAIL DISPATCHER (GITHUB CLOUD RUNNERS)
Naka-deploy ang 3 autonomous cloud workflows sa **GitHub Global Cloud Infrastructure**:
1. **Hourly Executive Reports to Gmail (`titan_24_7_cloud_autonomous_monitor.yml`):**
   * Tumatakbo tuwing ika-0 minuto ng bawat oras (`0 * * * *`).
   * Nagpi-ping sa 6 CDN endpoints at nagpapadala ng buong status report sa iyong Gmail (`mckinsyo01@gmail.com`).
2. **Inbound Reply Parser & AI Closer (`titan_24_7_inbound_ai_closer.yml`):**
   * Tumatakbo bawat 15 minuto (`*/15 * * * *`).
   * Kumokonekta sa SpaceMail IMAP server (`mail.spacemail.com:993`) para basahin ang mga sagot ng kliyente at i-draft ang tugon.
3. **Self-Healing Bounce Recovery (`titan_24_7_bounce_recovery.yml`):**
   * Tumatakbo bawat 2 oras (`0 */2 * * *`).
   * Ina-audit ang mga email bounces at kumukuha ng kapalit na C-level executives.

> **Physical Reality:** Tumatakbo ito sa mga server ng GitHub/Microsoft sa cloud — **walang kinalaman kung bukas o patay ang iyong laptop/desktop**.

## 🐳 LAYER 3: ANG ALWAYS-ON 24/7 CLOUD WORKER CONTAINER (RENDER / RAILWAY / CLOUD RUN)
Para sa mga continuous background loops na nangangailangan ng sub-second heartbeat:
* Gumawa tayo ng **`hospital_leads_database/Dockerfile`** at **`hospital_leads_database/render.yaml`**.
* Maaari itong i-deploy bilang isang **Always-On Free/Low-Cost Background Cloud Worker** sa Render.com, Railway.app, o Google Cloud Run.
* Ito ang magpapatakbo ng `hourlyMasterDaemon.js` nang tuluy-tuloy 24 oras sa isang araw, 365 araw sa isang taon.
